# Website usability review — 11 October 2026

This pass exercised the current localhost application and corrected reproducible usability problems. It supplements the security audit; it does not claim exhaustive testing on every device or a production penetration test.

## Findings corrected

- Project keyword search previously ignored secondary technologies, role and README details. It now shares matching with global search, supports combined words and accent-insensitive queries, and the technology selector includes all declared technologies. A technology filter checks declared tags; keyword search deliberately searches the broader project content.
- Legacy mock CSS hid project selectors on mobile without providing a reveal button. Technology, status and sort controls now remain available. Active filters have a clear action that retains list/grid preference, and result counts are announced.
- The global search field now retains the submitted query on the results page.
- Administrative posts followed stored order and offered move arrows even though the public feed orders by publication time. The admin list now uses the same timestamp ordering; post move arrows are removed and the ordering rule is explained. Projects and section entries retain manual reordering.
- Imported README summaries in admin lists showed HTML comments and Markdown source. The summaries now show readable plain text; the full document remains available in Preview/Edit.
- Admin navigation on small screens required horizontal scrolling to discover management pages. A labeled section selector exposes every admin destination below 900 px; desktop navigation stays available above that breakpoint. Existing unsaved-change guards are retained.
- Editor dialogs showed two Save buttons. They now provide one footer Save action, disable it while saving/uploading/framing, and announce pending operations. Focus skips controls inside closed GitHub connection panels and starts at the first available form field.
- Markdown editing displays a character count and the 30,000-character content limit. This is distinct from the 20 MiB upload limit.
- Focusing a link inside a collapsed post expands it so keyboard users can see the focused content.
- Switching publication tabs resets the category filter to avoid an unrelated category hiding draft/hidden results.
- Direct contact channels were hidden along with the mobile sidebar. They now appear below the contact form on small screens.

## Validation performed

- Automated checks: 58 tests pass, including new regressions for secondary-technology/combined-field search, admin/feed ordering across publication states, and readable README summaries. Existing authorization, private projection, upload access, CSRF, duplicate checks and credential encryption tests remain passing.
- ESLint, strict TypeScript, formatting and production compilation were checked after the changes.
- Browser checks used the connected in-app browser at actual 390 CSS px and 1440 CSS px; the temporary viewport override was reset afterward.
- Visited profile, projects, project detail, activity, global search, contact, GitHub and admin. Tested project keyword search, technology selection, clearing filters, list view, English/Vietnamese interface switching, dark/light mode, read-more, guest preview and absence of edit controls/private status tabs in guest mode.
- Mobile admin checks covered section navigation, project/post/skill/section lists and the new-project editor. Verified Markdown heading/emphasis/table preview, one Save button, initial input focus, unsaved-change warning, Continue editing and explicit discard. Trial content was discarded, without saving changes to owner content.
- Contact form rejects an empty submission through required-field validation. No test message was sent to the owner's inbox in this pass; submission and inbox behavior are covered by the isolated automated API suite.
- No document-level horizontal overflow was observed on the inspected routes at the measured widths. Project README tables rendered and no completed broken image was detected on the inspected project detail/GitHub views. No captured browser error log remained in the final QA tab.

## Remaining improvements and limits

- Imported README posts remain long technical documents. For a recruiter-facing portfolio, owner-written summaries of the problem, personal contribution, outcome and demo would make the feed easier to scan. These are editorial decisions, not automatically rewritten content.
- Route-specific document titles/descriptions and social preview images would improve browser-tab identification and shared links. The current public metadata mainly identifies the profile owner.
- This pass did not test physical phones, a full screen-reader workflow, real email delivery, production hosting/HTTPS/persistent storage, or real GitHub permission grants. A real uploaded CV was not available for a fresh visual PDF check; existing PDF/upload regression tests passed.
- Bilingual interface controls do not translate owner-authored text or imported repository documents. Those retain their source language.
- Security regressions passing is evidence for the tested paths, not a guarantee that every vulnerability has been excluded.
